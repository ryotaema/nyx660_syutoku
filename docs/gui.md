# GUI の使い方

撮影・録画・アノテーションなどを，ボタンを押すだけで実行できる画面です．
コマンドを覚えなくても，このページの手順だけで一通り使えます．

```bash
python3 nyx660_script/gui.py
```

GUI の「使い方」ボタンからもこのページを開けます．

## 画面の見方

```
┌──────────────────────────────────────────────┐
│ カメラ   [NYX660 (シリアル: …  IP: …) ▼] [再検出] │ ← 使うカメラ
│ タグ     [            ]                      │ ← 保存フォルダ名に付ける名前（任意）
│ 撮影設定 カラー解像度 [既定 ▼]  FPS [既定 ▼]    │ ← 必要なときだけ変える
├ 画像 │ 点群 │ 動画 │ タイムラプス │ 推論・アノテーション │ ツール ┤
│ [ボタン]  説明                                │
│           操作: 押すキー                       │ ← カメラ映像の画面で押すキー
├──────────────────────────────────────────────┤
│ 状態        [停止] [使い方] [保存先を開く]     │
│ ログ（実行中のメッセージ・エラー）              │
└──────────────────────────────────────────────┘
```

### 基本の流れ

1. **カメラを確認する** — 「カメラ」に NYX660（シリアル・IP）が出ていることを確認します．出るまで数秒かかります．2台以上つないでいるときは▼で選びます．
2. **（任意）タグを入れる** — 場所や条件の名前（例: `greenhouse`）を入れると，保存フォルダ名の末尾に付きます．ファイル名には付きません．
3. **タブを選んでボタンを押す** — カメラ映像のウィンドウが開きます．
4. **キーで操作する** — ボタン横の「操作」に書かれたキーを押します．**キーはカメラ映像のウィンドウを選んだ状態で押してください**（GUI 側ではありません）．
5. **終わったら** — `q` で終了するか，GUI の「停止」を押します．「保存先を開く」で保存されたフォルダが開きます．

同時に実行できるのは1つだけです．実行中は他のボタンが押せなくなります．

### 共通の設定

| 項目 | 内容 |
|---|---|
| カメラ | 使うカメラ．起動時に LAN 上の NYX660 を自動で探します．つなぎ直したら「再検出」 |
| タグ | 保存フォルダ名に付ける任意の名前．例: `nyx_260707_101741_greenhouse/` |
| 撮影設定 | カラー解像度・FPS をその回だけ変えます．「既定」のままなら `config.yaml` の値（通常カラー 1600x1200・30 FPS）．カラーは 640x480 / 1600x1200 の2つだけ選べます．深度は常に 640x480．FPS は 30 まで |

撮影設定はカメラを使うボタンにだけ効きます（変換・グラフ作成などには関係しません）．

### 下の部分

| 項目 | 内容 |
|---|---|
| 状態 | 「待機中」「実行中: …」などを表示 |
| 停止 | 実行中の処理を止めます．撮ったデータは保存されたまま安全に終了します．1回目で止まらないときは，もう一度押すと強制終了します |
| 使い方 | このページを開きます |
| 保存先を開く | 最後に使った機能の保存フォルダを開きます |
| ログ | スクリプトのメッセージ．エラーが出たときはここを見ます |

## タブごとの機能

保存先はすべて `nyx660_script/config.yaml` の `output` で決まります（既定はリポジトリ内の `data/`）．
保存されるファイルの詳細は [data_format.md](data_format.md) を参照してください．

### 画像

学習用の画像を集めるときに使います．

| ボタン | すること | 操作 | 保存先 |
|---|---|---|---|
| 1枚ずつ撮る | カラー・深度・深度カラーマップ・IR を1枚ずつ保存（PLY なし） | `s` 保存 / `q` 終了 | `data/images/` |
| 全データを1枚ずつ撮る | `s` を押すたびに RGB・深度・IR・PLY・カメラ情報をまとめて保存 | `s` 保存 / `q` 終了 | `data/images/` |
| 全データを1枚だけ撮る | 露光が落ち着くまで約2秒待ち，全データを1組だけ保存して自動で終わる | 押すだけ | `data/images/` |
| 連続で撮る | `Enter` で開始し，毎フレーム保存し続ける | `Enter` 開始 / `q` 終了 | `data/images/` |

迷ったら「1枚ずつ撮る」，あとで3次元の処理もしたいデータは「全データを〜」を使います．

### 点群

物体の3次元データを撮り，複数の向きから撮った点群を1つにまとめるときに使います．

1. 上の設定を決めます．
   - **自動で N 枚**: `Enter` を押すと N 枚を自動で撮ります．
   - **手動で**: `s` を押すたびに1枚撮ります．
   - **color を depth に位置合わせして保存**: カラー画像を深度と同じ 640x480・同じ視点に変換して保存します．カラーに描いた BBox で深度・点群を切り出したいときに使います．普段はオフ（元の解像度のまま保存）．
2. 「点群を撮る」を押して撮影します（保存先: `data/pointcloud/`）．
3. 「点群をつなぎ合わせる」を押し，2. で撮ったフォルダを選びます．結果は同じフォルダに `*_merged_pc.ply` として保存されます．
   - 物体を回しながら撮った場合は「物体を回しながら撮った」にチェックを入れます（前のフレームに順につなぎます）．
   - カメラも物体も動かさずに撮った場合はチェックなしのままにします（全フレームを1枚目に合わせます）．

つなぎ合わせには `open3d` が必要です（[setup.md](setup.md)）．
撮った点群は CloudCompare で見られます（[pointcloud_viewer.md](pointcloud_viewer.md)）．

### 動画

| ボタン | すること | 操作 | 保存先 |
|---|---|---|---|
| 録画する | カラー動画と深度カラーマップ動画（.mp4）を保存 | `Enter` 開始 / `q` 終了 | `data/mp4/` |
| YOLO検出付きで録画する | 検出結果と距離を描いた動画（.mp4）を保存 | モデルを選択 → `Enter` 開始 / `q` 終了 | `data/mp4/` |

### タイムラプス

植物などを長時間，一定間隔で撮り続けるときに使います．

1. 「○分ごとに」「○時間撮影する」を決めます．
2. 必要なら次にチェックを入れます．
   - **YOLO検出もする**: 開始時にモデルを選ぶと，検出結果の画像と `detection_log.csv` も保存します．
   - **深度の色を画面内の近い〜遠いで付ける**: 深度カラーマップを，その画面の中で一番近い〜一番遠いで色分けします（近い範囲だけを撮るときに見やすくなります）．
3. 「タイムラプスを開始」を押します．止めるときは「停止」を押します（それまでのデータは残ります）．
4. YOLO 検出付きで撮った場合は，「検出結果をグラフにする」でフォルダを選ぶと `analysis.png`（検出数・信頼度の推移）を作ります．

保存先: `data/timelapse_data/`

### 推論・アノテーション

| ボタン | すること | 操作 | 保存先 |
|---|---|---|---|
| YOLOで検出する | カメラ映像にリアルタイムで検出結果と距離を表示（保存しない） | モデルを選択 → `q` 終了 | なし |
| クリックで座標を記録 | 映像上の対象をクリックし，画像と座標を保存 | クリック → `s` 保存 / `q` 終了 | `data/click_test_data/` |
| BBoxアノテーション | 画像フォルダを選び，YOLO 形式のラベル（.txt）を付ける | フォルダを選択 → 下表 | 画像と同じ場所 |

BBox アノテーションの操作:

| キー/操作 | 動作 |
|---|---|
| 左ドラッグ（空白） | BBox を新しく作る |
| 左ドラッグ（角） | BBox の大きさを変える |
| 左ドラッグ（内部） | BBox を動かす |
| `d` / `a` | 次 / 前の画像（`d` は自動で保存） |
| `s` | 保存 |
| `c` | 前の画像の BBox をコピー |
| `z` | 直前の BBox を取り消し |
| `Delete` | 選択中の BBox を削除 |
| 矢印キー | 選択中の BBox を1px 動かす |
| `q` | 終了 |

### ツール

| ボタン | すること |
|---|---|
| 旧データの名前を変換 | 2026年7月より前の命名（`imageN_YYYY-MM-DD_…`）のデータを今の命名規則に揃えます．別ウィンドウで「変換前 → 変換後」を確認してから実行できます．既定はコピーなので元のデータは残ります（[legacy_conversion.md](legacy_conversion.md#旧命名データの変換)） |
| 旧形式の点群を変換 | 2026年10月より前に保存した PLY（mm 単位・SDK の座標系）を今の形式（m 単位・RealSense Viewer 座標系）に変換します．フォルダを選んだあと「いいえ」なら変換対象をログに出すだけ，「はい」で変換します．元のファイルは `*.ply.mm_bak` として残ります（[legacy_conversion.md](legacy_conversion.md#旧形式の点群-ply-の変換)） |
| 点群に色を付ける | 色の無い（CloudCompare で灰色になる）古い PLY に，同じショットのカラー画像の色を付けます．「いいえ」なら対象をログに出すだけ，「はい」で実行します（[legacy_conversion.md](legacy_conversion.md#点群に色を付ける)） |
| 点群の歪みを補正 | PLY の座標を，ToF レンズの歪みを補正した位置に直します．カメラの SDK の点群は歪みを補正しておらず，画面の端ほど横にずれます（中央値 約2cm，端の遠い点で最大 約20cm）．形を正確にしたいときに使います．補正済みの PLY は自動でスキップするので，何度実行しても大丈夫です．元のファイルは `*.ply.raw_bak` として残ります（[legacy_conversion.md](legacy_conversion.md#点群の歪みを補正)） |
| カメラパラメータ調整 | 露光時間などを振りながら撮り比べ，YOLO の検出結果で比べるツールを別ウィンドウで開きます |

## 困ったとき

| 症状 | 確認すること |
|---|---|
| 「カメラが見つかりません」 | LAN ケーブル・PoE の電源，PC 側の IP（`192.168.1.100/24`）を確認して「再検出」．閉じた直後は数秒見つからないことがあります |
| 「検出できません」 | ログに出る SDK のエラーを確認．SDK の場所（`config.yaml` の `sdk_path`，[setup.md](setup.md#sdk)） |
| キーを押しても反応しない | カメラ映像のウィンドウをクリックして選んでから押す．日本語入力がオンになっていないか |
| ボタンが押せない | 他の処理が実行中です．終わるのを待つか「停止」 |
| 「エラーで終了しました」 | ログの最後の数行に原因が出ます．解像度・FPS を変えている場合は「既定」に戻して試す |
| 映像が止まる・途切れる | ギガビットで接続できているか（LAN ランプ黄）．FPS を下げる |
| 「保存先を開く」で開かない | ログに理由が出ます．Docker 内ではファイルマネージャーが必要（[setup.md](setup.md#docker環境内で利用する場合任意)） |

GUI でできない細かい設定（露光・フィルタなどのカメラパラメータ，点群のパラメータなど）は，コマンドラインのオプション（[usage.md](usage.md#cli-オプション)）か `config.yaml` を使ってください．
